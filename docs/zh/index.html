痛点

Claude Code 的会话总在四处流浪。

一会儿在 checkout-api 里和 Claude 改代码， 切到 storefront-web 验证，再开个 tmux 跑测试 —— 到周五下午，你已经忘了哪个会话在哪个分支上跑到哪了。

把 Claude 包成一个按钮一堆的界面不是答案 —— CLI 本身就是产品。 Quiver 不重写 Claude Code，它管理的是 Claude 周围的那些窗口： 活的、置顶的、可搜索的，外加平时本来就要并排打开的那些东西。

能做什么

所有会话、所有项目，一个画面。

01 · 侧栏

跨项目，一眼看完。

所有 repo 下的会话按项目归类，状态点实时显示。 常用的两个项目置顶。会话标题、首条 prompt、路径 —— 全部可搜索。

02 · 终端

真实的 Claude TUI，不是包壳。

真 PTY 跑的是和你 shell 里完全一样的 claude —— Nerd Font、oh-my-zsh 主题、vim 快捷键、⌥ 跳词，全部正常。 没有任何行为差异。

03 · Diff & 文件

边聊边看 Claude 改了什么。

右侧自动跟随当前会话的工作目录。 切到 Changes 标签可以看实时 git status， 点击任何文件都会弹出对比视图。不用再开一个 IDE。

04 · Shell

另开一个 pane，做别的事。

下半屏一个 zsh 面板，跑测试、看 git log、起 build —— 和上面会话同一个目录。⌃` 一键切换。

进入会话

任何对话一键恢复。

侧栏顶部的 OPENED 跟踪正在跑的会话， RECENT 让你不用记得"上周那个 bug 是在哪个目录里讨论的"。 直接点，从上次结束的地方继续。

  • 会话直接读 ~/.claude/projects/，没有自己的私有格式。
  • 标题自动从对话里提取；不满意可以双击改名。
  • 状态点反映真实状态：运行中、等用户输入、空闲、已完成。

不用切来切去

你本来就要开的那个 shell，直接内置。

Quiver 不取代你的终端 —— 它把那个本来就跟 Claude 并排开着的 shell 收编进来。 同一个 shell、同一个 cwd、同一份 dotfiles。 git diff 看 Claude 刚改的东西，跑测试、回答 Claude 的下一个 prompt， 全程不用 alt-tab。
